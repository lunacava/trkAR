Files for video generation

From a take recorded with trkAR, this makes the intermediate files to hand to a video generation model that accepts references. The idea: the camera move and where the person stands come from the take, and the look comes from generation.

  • The target is a video generation model that takes videos and images as references (input) and is directed with a text prompt
  • trkAR does not generate anything itself. You choose which model or service to use (follow each service's pricing and terms of use)

How to make them

  1. In the Blender add-on trkAR Camera 0.10.21 or later, select a take (Getting started)
  2. Press Export Generation Inputs in Recording & Takes. The number next to it is the long side of the reference video (960 by default); the camera icon turns the location layout on or off
  3. If Range is set, only that range is written. Match it to the model's length limit (often 5–10 seconds)
  4. for_generation/ is created in the take's folder. Writing again keeps the previous one as for_generation_<date>/

The files

FileWhat it isHow to give it to the model
reference.mp4The set rendered in one flat gray clay color with the take's camera move. The person is a white outline taken from the live video, filled blackReference video (motion and framing reference, motion / structure control). <Video 1> in the prompt
layout.pngA 2×2 image looking forward (away from the camera), right, back (toward the camera) and left from where the person standsReference image (location). <Picture 1>
actor.jpgA frame from the take's live video where the person is large, sharp and well exposed, with everything outside the person grayed outReference image (person). <Picture 2>
prompt.txtA prompt template (in English) that points to the three files above. Add who, doing what, and the light and mood on the last lineText instruction
first_frame.pngThe live video's first frame of the rangeFirst frame (the start image for image-to-video models)
camera.jsonCamera position, rotation and field of view per frame (Blender world, Z up, meters)For tools that take a camera path
manifest.jsonWhat each file is, its size, fps and frame count, and the mapping aboveFor reading from scripts

Models name references differently (<Video 1>, @video1, [ref1] and so on) and accept different numbers of references. Rewrite how the prompt points to them to match the model's documentation. If the model takes only one reference image, use actor.jpg.

How to give them to each model

Give the same files to each model as below. Models differ in how they name references, how many they take and how long a video can be, so rewrite <Video 1> / <Picture N> in prompt.txt to the model's style. Follow each service's pricing and terms of use (as of November 2026).

Model (provider)How to pass the filesNames in the promptLength
MiniMax H3 reference-to-video (fal.ai)reference.mp4 as the reference video, layout.png and actor.jpg as reference images (in the API, reference_video_urls and reference_image_urls; upload the files to fal.ai first to get URLs)Video 1, Image 1, Image 25–15 s
MiniMax H3 (MiniMax API)In /v2/video_generation, list the text, the reference images (role: reference_image) and the reference video (role: reference_video) in content. Files are embedded as data URLs, up to 64 MB in totalVideo 1, Image 1, Image 25–15 s
Models that remake a base video (such as Kling's video edit)reference.mp4 as the base video, actor.jpg and layout.png as reference images. The base video may have size rules (Kling needs a height of 700 px or more and square pixels; export with a larger long side)As the model's documentation saysDepends on the model (often up to 10 s)
Models that start from a first frame (image-to-video)first_frame.png as the first frame. Describe the motion in the prompt (the camera move is hard to reproduce)–Depends on the model

Some models refuse images with faces of real people. In that case leave out actor.jpg and describe the person in the prompt.

Sending them automatically (example)

To go straight on to generation after exporting, turn on After Generation Inputs in the add-on's after-take command settings (0.11.9 or later) and use the example examples/fal_h3_generate.py. It sends for_generation/ to MiniMax H3 on fal.ai and downloads the video to for_generation/results/<time>/h3.mp4.

python3 ~/trkar/fal_h3_generate.py {for_generation} --event {event} --allow-external

  • It is charged to your own fal.ai account. Pass the key in the environment variable FAL_KEY (do not write it in the command or a file)
  • Add --allow-external once you have the consent of the people in the take. Without it nothing is sent
  • Describe the shot by editing the last line of prompt.txt, or pass --shot "…"
  • To send to another service or your own cloud, change where this example sends. The format of the files is in section 6 of INTEGRATION.en.md

Tips

  • The person outline needs a person mask. When recording, use the iPhone's MASK (alpha on the video) or DPT (person mask), or the AI cut-out on the PC (Matte with RVM; see "Cutting out people" in Getting started). RVM gives a finer outline. Without a mask, the reference video shows only the clay set
  • Match the fps: the reference video keeps the take's fps (recording is 24 fps by default). If the model assumes another fps, the speed changes, so record at a rate that suits the model
  • The aspect ratio follows the Blender scene's output. If the model only accepts certain ratios, set the scene's output resolution first
  • Before sending a photo of a person to an external service, get the consent of the person in it
