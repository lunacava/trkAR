Files for video generation

From a take recorded with trkAR, this makes the intermediate files to hand to a video generation model that accepts references. The idea: the camera move and where the person stands come from the take, and the look comes from generation.

  • The target is a video generation model that takes videos and images as references (input) and is directed with a text prompt
  • trkAR does not generate anything itself. You choose which model or service to use (follow each service's pricing and terms of use)

How to make them

  1. In the Blender add-on trkAR Camera 0.10.21 or later, select a take (Getting started)
  2. Press 生成用の素材を書き出す (Write files for generation) in 録画・テイク (Recording / Takes). The number next to it is the long side of the reference video (960 by default); the camera icon turns the location layout on or off
  3. If 範囲 (Range) is set, only that range is written. Match it to the model's length limit (often 5–10 seconds)
  4. for_generation/ is created in the take's folder. Writing again keeps the previous one as for_generation_<date>/

The files

FileWhat it isHow to give it to the model
reference.mp4The set rendered in one flat gray clay color with the take's camera move. The person is a white outline taken from the live video, filled blackReference video (motion and framing reference, motion / structure control). <Video 1> in the prompt
layout.pngA 2×2 image looking forward (away from the camera), right, back (toward the camera) and left from where the person standsReference image (location). <Picture 1>
actor.jpgA frame from the take's live video where the person is large, sharp and well exposed, with everything outside the person grayed outReference image (person). <Picture 2>
prompt.txtA prompt template (in English) that points to the three files above. Add who, doing what, and the light and mood on the last lineText instruction
first_frame.pngThe live video's first frame of the rangeFirst frame (the start image for image-to-video models)
camera.jsonCamera position, rotation and field of view per frame (Blender world, Z up, meters)For tools that take a camera path
manifest.jsonWhat each file is, its size, fps and frame count, and the mapping aboveFor reading from scripts

Models name references differently (<Video 1>, @video1, [ref1] and so on) and accept different numbers of references. Rewrite how the prompt points to them to match the model's documentation. If the model takes only one reference image, use actor.jpg.

Tips

  • The person outline needs a person mask. When recording, use the iPhone's MASK (alpha on the video) or DPT (person mask), or the AI cut-out on the PC (RVM で切り抜く, Cut out with RVM; see "Cutting out people" in Getting started). RVM gives a finer outline. Without a mask, the reference video shows only the clay set
  • Match the fps: the reference video keeps the take's fps (recording is 24 fps by default). If the model assumes another fps, the speed changes, so record at a rate that suits the model
  • The aspect ratio follows the Blender scene's output. If the model only accepts certain ratios, set the scene's output resolution first
  • Before sending a photo of a person to an external service, get the consent of the person in it
