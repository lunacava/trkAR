生成用の素材

trkAR で録ったテイクから、参照 (リファレンス) を入れられる動画生成モデルに渡す中間ファイルを作ります。カメラの動きと人の位置はテイクのとおり、見た目は生成で作る、という使い方のためのものです。

  • 対象となるモデルは、参照 (リファレンス) として動画と画像を入力でき、プロンプトで指示できる動画生成モデルです
  • trkAR は生成そのものはしません。ファイルをどのモデル・サービスに渡すかは自由です (費用・利用規約はそれぞれのサービスのものに従ってください)

作り方

  1. Blender アドオン trkAR Camera 0.10.21 以降で、テイクを選びます (はじめかた)
  2. 録画・テイク の 生成用の素材を書き出す を押します。横の数字は参照の動画の長い辺 (既定 960)、カメラのアイコンは場所のレイアウトを作るか
  3. 範囲 を入れていれば、その範囲だけを書き出します。モデルの長さの上限 (多くは 5〜10 秒) に合わせてください
  4. テイクのフォルダの中に for_generation/ ができます。もう一度書き出すと、前のものは for_generation_<日時>/ として残ります

できるファイル

ファイル中身モデルへの渡し方
reference.mp4テイクのカメラの動きで、背景のシーンを灰色の粘土 1 色で描いた動画。人は実写から取った白い輪郭線で、中は黒参照の動画 (動き・構図の参照、モーション / ストラクチャーの制御)。プロンプトの <Video 1>
layout.png人の立ち位置から 前 (カメラの奥)・右・後ろ (カメラの方)・左 を見た 2×2 の画像参照の画像 (場所)。<Picture 1>
actor.jpgテイクの実写から、人が大きく・くっきり・明るさの合ったコマを選び、人の外を灰色にした写真参照の画像 (人)。<Picture 2>
prompt.txt上の 3 つを指し示すプロンプトのひな形 (英語)。最後の行に、誰が・何をして・どんな光と雰囲気かを書き足します文章の指示
first_frame.png範囲の最初のコマの実写最初のコマ (画像から動画を作るモデルの開始の画像)
camera.jsonフレームごとのカメラの位置・向き・画角 (Blender のワールド、Z 上、m)カメラの軌跡を受けるツール向け
manifest.json各ファイルの意味・大きさ・fps・フレーム数と、上の当てはめ方スクリプトから読むとき

モデルによって参照の名前 (<Video 1>、@video1、[ref1] など) や、受けられる参照の数が違います。プロンプトの指し方はモデルの説明に合わせて書き換えてください。参照の画像が 1 枚しか入らないモデルなら、actor.jpg を優先します。

モデルごとの渡し方

同じ素材を、モデルごとに次のように渡します。参照の呼び方と数、長さの上限はモデルで違うので、prompt.txt の <Video 1>・<Picture N> をそのモデルの書き方に直します。値段と利用規約は各サービスのものに従ってください (2026 年 11 月時点の内容です)。

モデル (提供元)素材の渡し方プロンプトの呼び方長さ
MiniMax H3 reference-to-video (fal.ai)reference.mp4 を参照動画、layout.png・actor.jpg を参照画像 (API では reference_video_urls・reference_image_urls。ファイルは先に fal.ai に上げて URL にする)Video 1・Image 1・Image 25〜15 秒
MiniMax H3 (MiniMax の API)/v2/video_generation の content に、文・参照画像 (role: reference_image)・参照動画 (role: reference_video) を並べる。ファイルは data URL で埋め込み、全体で 64MB までVideo 1・Image 1・Image 25〜15 秒
動画を土台に作り替えるモデル (Kling の video edit など)reference.mp4 を土台の動画、actor.jpg や layout.png を参照画像に。土台の動画の高さや画素の比に決まりがあることがある (Kling は高さ 700px 以上・1:1。書き出すときの長辺を大きくする)各モデルの説明に合わせるモデルによる (10 秒までが多い)
最初のコマから作るモデル (image-to-video)first_frame.png を最初のコマに。動きはプロンプトで書く (カメラの動きは再現されにくい)―モデルによる

layout.png は Blender で描いたシーンそのものなので、そのまま渡すと、生成の背景が CG の質感に引っぱられやすくなります。同じ場所を写実的にしたルックの画像 (前・右・後ろ・左の 2×2) を <Picture 1> の代わりに渡すと、実写らしくなります。サンプルのシーン には、それぞれのルックの画像 (trkar_subway_platform_look_sheet.jpg・trkar_classroom_look_sheet.jpg) を付けています (Blender の画面をもとに AI の画像生成で写実化したもの)。

実在の人の顔を含む画像を断るモデルもあります。その場合は actor.jpg を渡さず、人の見た目をプロンプトで書きます。

自動で送る (見本)

書き出したら自動で生成まで流したいときは、アドオンの「テイクのあとに流すコマンド」で 生成用の素材のあと をオンにし (0.11.9 以降)、見本 examples/fal_h3_generate.py を指定します。for_generation/ を fal.ai の MiniMax H3 に送り、できた動画を for_generation/results/<日時>/h3.mp4 に落とします。

python3 ~/trkar/fal_h3_generate.py {for_generation} --event {event} --allow-external

  • 料金は自分の fal.ai のアカウントにかかります。鍵は環境変数 FAL_KEY で渡します (コマンドやファイルに書かない)
  • 写っている人の同意を取ったうえで --allow-external を付けます。付けないと何も送りません
  • 場面の説明は prompt.txt の最後の行を書き換えるか、--shot "…" で渡します
  • --look <画像> を付けると、layout.png の代わりにその画像を場所の参照 (<Picture 1>) として送ります (サンプルのシーンのルックの画像など)
  • ほかのサービスや自分のクラウドに送るときは、この見本の送り先を書き換えます。素材の決まりは INTEGRATION.md の 6 章 にあります

うまく作るこつ

  • 人の輪郭線には人物のマスクが要ります。録るときに iPhone の MASK (実写のアルファ) か DPT (人物マスク)、または PC で動かす AI Mask (AI Mask 適用、はじめかた の「人のマスク」) を使ってください。RVM のほうが人の外形が細かく出ます。マスクの無いテイクでは、背景の粘土だけの参照の動画になります
  • fps をそろえる: 参照の動画はテイクの fps のまま書き出します (既定の収録は 24fps)。モデルが別の fps を前提にしていると速さが変わるので、モデルに合う fps で録ってください
  • 縦横比は Blender のシーンの出力のままです。モデルが決まった比率しか受けないときは、シーンの出力の解像度を先に合わせます
  • 人の写真を外のサービスに送るときは、写っている人の同意を取ってください
